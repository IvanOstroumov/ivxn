La plupart des conseils sur l'automatisation sautent directement au code. La première étape vraiment utile est de déterminer ce qui vaut la peine d'être automatisé.

## Ce qui vaut la peine d'être automatisé

<Callout>
Un bon candidat à l'automatisation : vous faites les mêmes étapes, dans le même ordre, plus de deux fois, et les étapes elles-mêmes changent rarement. Un mauvais candidat : quelque chose qui nécessite un jugement à chaque fois, ou que vous ne ferez qu'une seule fois.
</Callout>

Cibles initiales courantes :
- Renommer ou organiser des lots de fichiers (téléchargements, exports, photos)
- Récupérer les mêmes données depuis la même source selon un calendrier
- Convertir des fichiers d'un format à un autre en masse
- Nettoyer des fichiers journaux ou d'anciens fichiers temporaires

## Un exemple réel : organiser un dossier de téléchargements en désordre

Voici un script complet et fonctionnel qui trie les fichiers d'un dossier en sous-dossiers par extension — une demande vraiment courante.

```python
import shutil
from pathlib import Path

SOURCE = Path.home() / "Downloads"

def organize_by_extension(source: Path):
    for file in source.iterdir():
        if file.is_dir():
            continue
        extension = file.suffix.lower().lstrip(".") or "no_extension"
        destination_folder = source / extension
        destination_folder.mkdir(exist_ok=True)
        shutil.move(str(file), str(destination_folder / file.name))

if __name__ == "__main__":
    organize_by_extension(SOURCE)
    print(f"Organized files in {SOURCE}")
```

Ce que cela fait, ligne par ligne : il examine chaque fichier directement dans le dossier Téléchargements, détermine son extension, crée un sous-dossier nommé d'après cette extension s'il n'existe pas encore, et y déplace le fichier. Exécutez-le une fois, et chaque `.pdf` finit dans un dossier `pdf/`, chaque `.jpg` dans un dossier `jpg/`, et ainsi de suite.

<Callout type="warning">
Testez tout script qui déplace des fichiers sur une copie d'un dossier d'abord, pas sur l'original — `shutil.move` ne demande pas de confirmation, et un bug dans une première ébauche peut déplacer des fichiers plus vite que vous ne pouvez les corriger à la main.
</Callout>

## Le planifier pour ne pas avoir à s'en souvenir

Un script ne fait gagner du temps que s'il s'exécute réellement sans que vous ayez à vous rappeler de le lancer.

- **Windows :** le Planificateur de tâches peut exécuter un script Python selon un calendrier (quotidien, à la connexion, etc.) sans rien avoir besoin d'installer d'autre que Python lui-même.
- **Linux/macOS :** `cron` fait le même travail — une entrée crontab d'une ligne peut exécuter le script chaque nuit.

## Où aller à partir de là

Une fois qu'un script simple fonctionne, les prochaines étapes naturelles sont : ajouter une gestion des erreurs pour les fichiers verrouillés ou en cours d'utilisation, journaliser ce qui a été fait (pour pouvoir vérifier plus tard au lieu de deviner), et — s'il touche à quelque chose d'important — un mode dry-run qui affiche ce qu'il *ferait* sans réellement le faire.
