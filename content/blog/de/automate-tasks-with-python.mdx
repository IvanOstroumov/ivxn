Die meisten Automatisierungsratschläge springen direkt zum Code. Der eigentlich nützliche erste Schritt ist herauszufinden, was sich überhaupt zu automatisieren lohnt.

## Was sich zu automatisieren lohnt

<Callout>
Ein guter Kandidat für Automatisierung: Du machst dieselben Schritte, in derselben Reihenfolge, mehr als ein paar Mal, und die Schritte selbst ändern sich selten. Ein schlechter Kandidat: etwas, das jedes Mal Ermessensentscheidungen braucht, oder das du einmal machst und nie wieder.
</Callout>

Häufige erste Ziele:
- Umbenennen oder Organisieren von Dateistapeln (Downloads, Exporte, Fotos)
- Regelmäßiges Abrufen derselben Daten von derselben Quelle
- Massenkonvertierung von Dateien von einem Format ins andere
- Aufräumen von Log-Dateien oder alten temporären Dateien

## Ein echtes Beispiel: einen unordentlichen Downloads-Ordner organisieren

Hier ist ein vollständiges, funktionierendes Skript, das Dateien in einem Ordner nach Erweiterung in Unterordner sortiert — eine wirklich häufige Anfrage.

```python
import shutil
from pathlib import Path

SOURCE = Path.home() / "Downloads"

def organize_by_extension(source: Path):
    for file in source.iterdir():
        if file.is_dir():
            continue
        extension = file.suffix.lower().lstrip(".") or "no_extension"
        destination_folder = source / extension
        destination_folder.mkdir(exist_ok=True)
        shutil.move(str(file), str(destination_folder / file.name))

if __name__ == "__main__":
    organize_by_extension(SOURCE)
    print(f"Organized files in {SOURCE}")
```

Was das Zeile für Zeile macht: Es schaut sich jede Datei direkt im Downloads-Ordner an, ermittelt ihre Erweiterung, erstellt einen nach dieser Erweiterung benannten Unterordner, falls noch keiner existiert, und verschiebt die Datei dorthin. Führe es einmal aus, und jede `.pdf` landet in einem `pdf/`-Ordner, jede `.jpg` in einem `jpg/`-Ordner, und so weiter.

<Callout type="warning">
Teste jedes Datei-verschiebende Skript zuerst an einer Kopie eines Ordners, nicht am Original — `shutil.move` fragt nicht nach Bestätigung, und ein Bug in einem ersten Entwurf kann Dateien schneller verlegen, als du sie von Hand korrigieren kannst.
</Callout>

## Es planen, damit du nicht daran denken musst

Ein Skript spart nur Zeit, wenn es tatsächlich läuft, ohne dass du dich erinnern musst, es auszuführen.

- **Windows:** Die Aufgabenplanung kann ein Python-Skript nach Zeitplan ausführen (täglich, bei Anmeldung usw.), ohne dass etwas außer Python selbst installiert werden muss.
- **Linux/macOS:** `cron` erledigt denselben Job — ein einzeiliger Crontab-Eintrag kann das Skript jede Nacht ausführen.

## Wo es von hier aus weitergeht

Sobald ein einfaches Skript funktioniert, sind die natürlichen nächsten Schritte: Fehlerbehandlung für gesperrte oder in Benutzung befindliche Dateien hinzufügen, protokollieren, was getan wurde (damit du später nachschauen kannst, statt zu raten), und — wenn es etwas Wichtiges berührt — ein Dry-Run-Modus, der ausgibt, was es tun *würde*, ohne es tatsächlich zu tun.
