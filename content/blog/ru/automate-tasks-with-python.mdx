Большинство советов по автоматизации сразу прыгают к коду. По-настоящему полезный первый шаг — понять, что вообще стоит автоматизировать.

## Что стоит автоматизировать

<Callout>
Хороший кандидат для автоматизации: вы делаете одни и те же шаги, в одном и том же порядке, больше пары раз, и сами шаги редко меняются. Плохой кандидат: то, что каждый раз требует субъективных решений, или то, что вы делаете один раз и никогда больше не сделаете.
</Callout>

Частые первые цели:
- Переименование или организация партий файлов (загрузки, экспорты, фото)
- Получение одних и тех же данных из одного и того же источника по расписанию
- Массовая конвертация файлов из одного формата в другой
- Очистка лог-файлов или старых временных файлов

## Реальный пример: организация захламлённой папки загрузок

Вот полноценный, рабочий скрипт, который сортирует файлы в папке по подпапкам по расширению — по-настоящему частый запрос.

```python
import shutil
from pathlib import Path

SOURCE = Path.home() / "Downloads"

def organize_by_extension(source: Path):
    for file in source.iterdir():
        if file.is_dir():
            continue
        extension = file.suffix.lower().lstrip(".") or "no_extension"
        destination_folder = source / extension
        destination_folder.mkdir(exist_ok=True)
        shutil.move(str(file), str(destination_folder / file.name))

if __name__ == "__main__":
    organize_by_extension(SOURCE)
    print(f"Organized files in {SOURCE}")
```

Что это делает построчно: смотрит на каждый файл прямо внутри папки загрузок, определяет его расширение, создаёт подпапку с именем этого расширения, если её ещё нет, и перемещает файл туда. Запустите один раз — и каждый `.pdf` окажется в папке `pdf/`, каждый `.jpg` — в папке `jpg/`, и так далее.

<Callout type="warning">
Сначала тестируйте любой скрипт, перемещающий файлы, на копии папки, а не на оригинале — `shutil.move` не спрашивает подтверждения, и баг в первом черновике может раскидать файлы быстрее, чем вы успеете исправить это вручную.
</Callout>

## Настройка расписания, чтобы не нужно было помнить

Скрипт экономит время, только если реально запускается без того, чтобы вы помнили о его запуске.

- **Windows:** планировщик заданий может запускать Python-скрипт по расписанию (ежедневно, при входе и т.д.) без необходимости устанавливать что-либо, кроме самого Python.
- **Linux/macOS:** `cron` делает то же самое — одна строка в crontab может запускать скрипт каждую ночь.

## Куда двигаться дальше

Как только простой скрипт заработал, естественные следующие шаги: добавление обработки ошибок для файлов, которые заблокированы или используются, логирование того, что было сделано (чтобы проверить позже, а не гадать), и — если скрипт трогает что-то важное — режим сухого прогона, который печатает, что скрипт *сделал бы*, не делая этого на самом деле.
