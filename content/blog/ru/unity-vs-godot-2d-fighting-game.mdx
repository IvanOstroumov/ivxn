Дебаты о движках склонны накаляться сильнее, чем заслуживает реальное решение. Вот честное обоснование выбора Unity конкретно для SAMT: All Stars.

## Реальные решающие факторы, по весу

<Callout>
Для жанра, столь чувствительного к таймингу, как файтинги, движок имеет меньшее значение, чем то, насколько намеренно вы строите специфичные для файтинга системы (хитбоксы, буферизация ввода, фрейм-дата) поверх него — большинство современных движков технически способны справиться с этой задачей.
</Callout>

1. **Предыдущий опыт и знакомство с существующим инструментарием** — строить на движке, который я уже хорошо знал, означало больше времени на реальные системы игры и меньше на переизучение специфичных для движка рабочих процессов.
2. **Экосистема ассетов и плагинов** — более долгая история Unity означает более глубокий пул существующих инструментов и решений сообщества для специфичных для жанра проблем (визуализация хитбоксов, утилиты обработки ввода), что снизило количество построенного полностью с нуля.
3. **Зрелость 2D-инструментария** — специфичные для 2D инструменты Unity (обработка спрайтов, 2D-физика, анимация) были достаточно зрелыми для нужд проекта без дополнительных плагинов.

## Где Godot — подлинно сильная альтернатива

Godot закрыл большую часть разрыва в последних версиях — его система сцен, пожалуй, более интуитивна для проектов, ориентированных на 2D в первую очередь, он полностью с открытым исходным кодом без условий лицензирования для отслеживания, и его GDScript (или C#, если предпочтительнее) доступен для изучения. Для команды без предыдущего опыта конкретно с Unity, или той, что приоритизирует инструментарий с открытым исходным кодом с самого начала, Godot — легитимный первый выбор, а не просто запасной вариант.

## Сравнительная таблица

| | Unity | Godot |
|---|---|---|
| Зрелость 2D-инструментария | Сильная, давно устоявшаяся | Сильная, пожалуй более 2D-нативная по дизайну |
| Лицензирование | Коммерческое, условия менялись со временем — проверьте текущие правила | Полностью с открытым исходным кодом (MIT), без проблем лицензирования |
| Глубина экосистемы/плагинов | Больше, более долгая история | Меньше, но стабильно растёт |
| Поддержка C# | Нативная и зрелая | Поддерживается, GDScript — более нативно ощущающийся вариант |
| Кривая обучения при незнании обоих | Умеренная | Часто считается немного мягче для проектов, ориентированных на 2D в первую очередь |

## Что реально формировало ощущение файтинга (независимо от движка)

Независимо от движка, системы, которые делают файтинг отзывчивым и справедливым, строятся поверх любого выбранного движка, а не предоставляются им: точная [обработка хитбоксов/хёртбоксов](/blog/hitbox-hurtbox-fighting-games), последовательная фрейм-дата, и намеренная буферизация ввода. Правильное выполнение этого значило гораздо больше для итогового ощущения, чем сам выбор Unity против Godot.

<Callout type="warning">
Выбираете движок для собственного проекта и разрываетесь между Unity и Godot? Честный ответ — оба могут хорошо работать — решающий фактор обычно существующее знакомство вашей команды и конкретные пробелы в инструментарии, которые нужно заполнить, а не универсально «лучший» движок.
</Callout>
