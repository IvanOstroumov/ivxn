Если вы начинаете Android-проект в 2026 году, вопрос выбора языка встаёт в первый же день. Вот практический ответ, а не теоретический.

## Короткая версия

Используйте **Kotlin** для всего нового. Java всё ещё законный выбор, если вы присоединяетесь к существующей большой кодовой базе на Java, но для нового Android-проекта начинать на Java больше нет веской причины.

## Почему победил Kotlin

<Callout>
Google сделала Kotlin рекомендуемым языком для Android в 2019 году. С тех пор Jetpack Compose, корутины и большинство новых платформенных API проектируются в первую очередь под Kotlin — поддержка Java сохраняется, но не приоритетна.
</Callout>

- **Null-безопасность встроена в систему типов.** `NullPointerException` — исторически одна из самых частых причин крашей на Android — становится ошибкой компиляции, а не рантайма.
- **Меньше шаблонного кода.** Data-классы, значения параметров по умолчанию и функции-расширения сокращают церемонии, которые Java требует для того же поведения.
- **Корутины** дают структурированную конкурентность без вложенных колбэков и ручного управления пулами потоков, которые нужны в асинхронной Java.

## Синтаксис бок о бок

Простой класс-данные на Java:

```java
public class User {
    private final String name;
    private final int age;

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() { return name; }
    public int getAge() { return age; }
}
```

То же самое на Kotlin:

```kotlin
data class User(val name: String, val age: Int)
```

Equality, `hashCode`, `toString` и семантика copy достаются бесплатно в версии на Kotlin — на Java всё это пришлось бы писать или генерировать отдельно.

## Сравнительная таблица

| | Kotlin | Java |
|---|---|---|
| Null-безопасность | Обеспечивается компилятором | Не обеспечивается (`Optional` — по желанию) |
| Шаблонный код | Мало (data-классы, значения по умолчанию) | Больше (геттеры/сеттеры, билдеры) |
| Асинхронность | Корутины (структурированные, отменяемые) | Потоки / колбэки / `CompletableFuture` |
| Jetpack Compose | Полноценная поддержка | Через интероп, не основной путь |
| Кривая обучения для Java-разработчиков | Несколько дней на основы | — |
| Существующие крупные кодовые базы | Меньше, новее | Всё ещё частые в старых корпоративных приложениях |

## Миграция существующей кодовой базы на Java

Переписывать всё с нуля не нужно. Android Studio умеет автоматически конвертировать отдельные файлы `.java` в `.kt`, а интероп Kotlin/Java прямой — класс на Kotlin может наследоваться от класса на Java, и наоборот, в одном модуле. Реалистичный путь:

1. Новые фичи и новые файлы с первого дня пишутся на Kotlin.
2. Файлы конвертируются по возможности, когда вы уже трогаете их ради багфикса или новой фичи.
3. Стабильные, редко изменяемые Java-файлы остаются как есть — конвертировать рабочий код без другой причины его трогать не стоит риска.
